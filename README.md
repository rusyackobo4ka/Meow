# Meow

Ассистент-подборщик комплектов мебели (стол + стул + лампа) по каталогу объявлений.
Один вызов обрабатывает один запрос покупателя и возвращает `clarify`, `ok` или `no_match`.

## Запуск

Зависимости устанавливаются заранее (см. `requirements.txt`, внешних нет — используется
стандартная библиотека). Рабочие ключи организатор выдаёт лично, в репозиторий они не
попадают.

```sh
./run --catalog /absolute/path/catalog.json < request.json > response.json
```

- Вход: один JSON-объект до EOF; выход: один JSON-объект до завершения процесса.
- В stdout — только ответ; логи — в stderr. Успешная обработка — код 0,
  ошибка запуска или внешнего сервиса — ненулевой код.
- На один запрос отводится до 120 секунд (включая вызовы модели).

## Переменные окружения

Подключение к модели читается из переменных окружения. Дефолтов нет: отсутствие —
техническая ошибка (подробно в `config.py`). Значения могут меняться в финальной проверке.

| Переменная | Назначение | Пример |
| --- | --- | --- |
| `LLM_BASE_URL` | Базовый URL API организаторов (http/https) | `https://api.example.org/v1` |
| `LLM_MODEL` | Идентификатор модели | `google/gemma-4-31B-it` |
| `LLM_API_KEY` | Ключ доступа (Bearer) | `replace-me` |
| `LLM_USER_AGENT` | Пользовательский агент запросов | `sfedu-hackathon-team-name/1.0` |

Локально можно положить файл `.env` рядом с репозиторием — `env_loader.py` подхватит
его при старте (уже заданные переменные не перезаписываются). В проверке окружение
выставляется организаторами, `.env` не требуется.

## Сетевые зависимости

- Только API модели организаторов (`LLM_BASE_URL`, `LLM_USER_AGENT`).
- Модель `google/gemma-4-31B-it` используется в модуле `extract.py`
  (`ConditionExtractor`) через `llm_client.py` (`LLMClient.complete_json`) для разбора
  запроса и истории диалога в структурированные условия.
- Транспорт — `urllib` из стандартной библиотеки, добавление пакетов не требуется.

## Структура

| Модуль | Ответственность |
| --- | --- |
| `config.py` | Конфигурация из env: `LLMConfig`, `AppConfig` (единственное место чтения окружения) |
| `llm_client.py` | Чистый HTTP-клиент модели, конфиг приходит снаружи |
| `extract.py` | Диалог → структурированные условия (`Conditions`) через LLM |
| `catalog.py` | Загрузка и фильтрация объявлений каталога |
| `selector.py` | Подбор комплектов в пределах бюджета |
| `dialog.py` | Вопросы для `clarify`, объяснения, сборка JSON-ответа |
| `assistant.py` | Оркестрация модулей (`BuyerAssistant`) |
| `main.py` | Точка входа; composition root: env → граф объектов → обработка запроса |

Сборка графа объектов делается только в `main.build_assistant`: доменные классы не
читают окружение и не создают свои зависимости сами.
